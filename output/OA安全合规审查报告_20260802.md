# OA 安防运维系统 · 安全合规性审查报告

- 审查对象：安防运维 OA 系统（Laravel 11 后端 `pc-api` + Vue3/TS 前端 `pc-web` + 部署脚本）
- 审查日期：2026-08-02
- 审查范围：安全合规（认证、授权、越权/IDOR、输入安全、审计、数据保护、前端凭证、部署配置、凭据管理）
- 审查方法：静态代码审查，关键结论已逐一核对源文件与 git 跟踪状态

---

## 二、高危发现详述（H1–H4）

### H1 · 系统性 IDOR（跨用户数据泄露）
**证据**
- `app/Http/Middleware/DataScope.php:57-71`：对 `admin/finance/manager/sales_manager` 直接 `return $next($request)` 旁路；对普通用户仅向 request **注入属性**（`$request->attributes->set('data_scope_user_id', …)`，第 76-77 行），**不自动追加 WHERE 条件**。
- 多个控制器直接以外部 `user_id` 过滤：`ExpenseController.php:44`、`EmployeeResignationController.php:44`、`ScheduleController.php:192`、`SystemLogController.php:17`、`AuditController.php:157`、`CustomerPipelineController.php:40` 均为 `if ($request->filled('user_id')) $query->where('user_id', $request->user_id)`。
- 对照安全写法：`AttendanceController.php:123/190` 使用 `Auth::id()`。

**风险**：普通用户/业务管理员可传入他人 `user_id` 读取其报销、排班、客户等数据，构成越权访问。
**建议**：列表接口禁止接受外部 `user_id`；统一以 `auth()->id()` 或显式鉴权（本人/管理员/经理）后再允许按他人查询；`DataScope` 改为在查询构造器上自动追加 scope 条件，而非仅注入属性。

### H2 · User 模型 fillable 过度开放（提权）
**证据**：`app/Models/User.php:26-31` `fillable` 含 `is_system`、`user_type`、`must_change_password`、`status`。
**风险**：若员工创建/更新接口未显式排除，攻击者可提交 `user_type=system` 或 `is_system=true` 自我提权为超级管理员。
**建议**：从 `fillable` 移除 `is_system/user_type`（仅在 `system` 专属路由用 `forceFill` 设置）；在 `StoreEmployeeRequest`/`UpdateEmployeeRequest` 中对这些字段 `deny()`。

### H3 · 登录限流被绕过 + 无 IP 维度
**证据**：`app/Http/Middleware/LoginThrottle.php:25`（白名单 `admin1/fin_wu/eng_qian/sales_yang`）、`:32-34`（命中即跳过计数与锁定）、`:36`（锁定键仅 `login:lock:{$username}`，无 IP）。
**风险**：白名单账号可被无限次撞库；攻击者换用户名分布式尝试可绕过单用户名锁定。
**建议**：移除生产环境白名单（或仅本地启用）；锁定键改为 `username+IP` 复合键；增加全局失败频率熔断。

### H4 · 前端 Token 明文存储
**证据**：`pc-web/src/utils/auth.ts:5,9,13` 使用 `localStorage` 存取 `oa_access_token`；`utils/request.ts:37` 拦截器自动携带；`views/disk/index.vue:680-682`、`api/analytics.ts:49-52` 直接读取并拼入 Authorization / iframe URL。
**风险**：任一 XSS（含未来误用 `v-html` 或第三方依赖被攻陷）即可读取 token 冒充用户；token 入 URL 易被 referrer/历史泄露。
**建议**：改用 Sanctum 支持的 `HttpOnly + Secure + SameSite=Strict` Cookie；或缩短 token 有效期并对敏感操作增加二次校验；移除 URL 传 token 做法。

## 三、凭据管理发现（H5，已澄清）

**事实核查**：`deploy/deploy_https_152.py:17-18` 的确在本地明文写入 152 生产服务器密码 `PASS/SUDO = "Aa782997781"`。但经 `git ls-files` + `git check-ignore -v` 核实：
- `deploy/` 整目录已被 `.gitignore:105` 忽略，**未进入版本库**；
- `pc-api/.env` 亦被 `.gitignore:18` 忽略，且当前内容为占位符（`APP_KEY=dummy…`、`DB_PASSWORD=` 空），**未泄露真实生产凭据**。

**结论**：H5 由"入库泄露（高）"下调为"本地明文存储（中）"。建议仍应：轮换该服务器密码、从工作区删除含明文密码的脚本、改用 SSH key + 环境变量；并确认生产 `.env` 由 `php artisan key:generate` 生成真实 `APP_KEY`。

## 四、中/低危发现（M1–L4）

- **M1 会话过期**：`config/sanctum.php:49` `expiration => null`，个人令牌无生命周期。建议设 `expiration`（如 43200 分钟）并支持主动吊销。
- **M2 授权放行过宽**：`CheckPermission.php` 对 `user_type=system`（35-37 行）与 `role=admin`（48-50 行）直接放行所有接口。`admin` 业务管理员可访问全部业务模块。建议 `admin` 按需授权而非全模块通杀。
- **M3 PII 明文**：`User` 的 `id_card/phone`、`EmployeeOnboarding.id_card_no`、`ConstructionTeamMember.id_card` 均明文 `fillable`，无 `encrypted` cast。建议对身份证号等使用 AES-256 `encrypted` cast，列表/导出脱敏。
- **M4 CORS**：`config/cors.php:20/31/37` `allowed_methods/headers='*'` 且 `supports_credentials=true`。建议生产收紧为具体 HTTPS 域名并限定实际动词。
- **M5 上传绕过**：统一 `FileUploadService`（finfo+MIME 白名单+UUID 命名）较安全，但 `RepairStepPhotoController`、`ExternalQuoteController`、`RepairOrderController`、`PortalController` 等直接 `storeAs(..., getClientOriginalExtension())`。建议统一走 `FileUploadService`；nginx 加 `location ~ /storage/.*\.php$ { deny all; }`。
- **M6 传输安全**：`install.sh:217-222` 仅 `listen 80` 且仅 `X-Frame-Options`；`oa-docker` nginx 连该头都无，亦无 CSP/HSTS。建议默认部署即启用 HTTPS + HSTS/CSP/`X-Content-Type-Options:nosniff`。
- **M7 依赖**：`install.sh:196` `composer config policy.advisories.block false` 放行已知安全公告包，仅应临时使用，部署后恢复并跑 `composer audit`。
- **L1–L4**：`.env.example` 暴露真实域名；`analytics.ts` token 入 URL；`xlsx@0.18.5` 升级或换 `exceljs`；`CheckResourceOwnership` 缺省策略改为"拒绝"。

## 五、合规良好项（正面）

- 密码哈希：`User.php:36` `'password' => 'hashed'`（bcrypt）+ `AuthController` 用 `Hash::make`，正确。
- 改密：弱密码黑名单 + 正则 + 长度校验，且撤销其他设备 token。
- 空密码登录 bypass 已修复（V1.2.7）。
- 审计日志对 `password/oldPassword/newPassword` 脱敏（`AuditLogger.php:109-117`）。
- 前端全局无 `v-html`/`innerHTML`，XSS 利用面低。
- `.env` 已被 `.gitignore` 正确忽略，未纳入版本控制。
- 绝大多数数据库访问使用 Eloquent/参数绑定，原始 SQL 普遍带 `?` 占位。

## 六、整改优先级

**P0（立即处置）**
1. H1 修复 IDOR：列表接口禁收外部 `user_id`，`DataScope` 改为自动追加 WHERE。
2. H2 收紧 `User::fillable`，移除 `is_system/user_type`。
3. H3 收窄 `LoginThrottle` 白名单 + 锁定键加 IP 维度。
4. H4 Token 改 HttpOnly Cookie 或缩短有效期。
5. H5 轮换 152 密码、删除本地明文脚本、改用 SSH key。

**P1（短期）**
- M1 token 过期；M3 PII 加密；M4 CORS 收紧；M6 默认 HTTPS+安全头；M5 上传统一。

**P2（持续改进）**
- M2 授权按需；M7 依赖审计；L1–L4 配置与依赖清理。
